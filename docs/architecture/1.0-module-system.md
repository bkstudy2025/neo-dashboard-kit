# Neo Dashboard – Modul-System & 1.0 Release-Architektur

> Status: **Entwurf / Diskussionsgrundlage** für den Schritt von Beta → 1.0.
> Dieses Dokument beschreibt das Zielbild. Es verändert noch keinen Produktivcode.

## Leitidee

Eine **einzige** Karte (`custom:neo-card`) ist die Hülle für alles. Der Nutzer
fügt nur diese eine Karte hinzu und wählt im Editor über ein Dropdown den
**Kartentyp**. Premium-Typen werden bei Bedarf nachgeladen und über eine
zentrale Lizenzprüfung freigeschaltet.

Vorbild ist Bubble Card (eine Karte, `card_type`-Auswahl). Neo geht darüber
hinaus durch: **Lazy-Loading pro Typ**, **Hot-Reload über versionierte
Element-Tags** und **sauberes Premium-Gating an einer Stelle**.

## Getroffene Entscheidungen

| Thema | Entscheidung |
|---|---|
| Karten-Granularität | **Eine Karte für alles** – alle Module sind `card_type`-Varianten unter `neo-card` |
| Editor-UX | **Dropdown „Kartentyp"**, gruppiert nach *Frei* / *Premium* |
| Modul-Modell | **Hybrid** – `type: card` (Voll-JS) ab 1.0; `type: layer` (deklarativ) im Schema reserviert, Auslieferung ab 1.1 |
| Store-Backend | **Index-Repo (`neo-modules`) + jsDelivr-CDN** statt GitHub-Discussions-Scraping |
| Modul-Laden | **dynamisches `import()` via Blob-URL + SHA-256-Integritätsprüfung** statt `<script>`-Injection |

## Warum „eine Karte" das Bloat-Problem löst

Heute existieren ~25 separate Premium-Karten (`neo-rooms-card`,
`neo-camera-card`, …, zusammen ~450 KB JS). Als eigenständige Karten würden sie
den Karten-Picker und die Resource-Liste überladen und müssten 25-fach
lizenz-gated werden.

| Problem (25 Karten) | Mit einer Karte |
|---|---|
| 25 Einträge im Picker | 1 Eintrag „Neo Card" |
| 25 Resource-/Bundle-Einträge | 1 Shell + Module on-demand |
| Nutzer rät, welche Karte | 1 Dropdown als Katalog |
| Premium-Gating × 25 | 1 Lizenzprüfung in der Shell |

Wichtig: Die Hülle entschlackt nur dann *wirklich*, wenn die Varianten **lazy**
geladen werden. Sonst lädt der Browser trotzdem alle 450 KB.

## Architektur

```
custom:neo-card (Shell, Core/kostenlos)
│
├─ liest card_type aus der Config
├─ Registry: kennt alle bekannten Typen + Metadaten (tier, version, tag)
├─ Lizenz-Gate: premium-Typen nur bei aktiver Lizenz
├─ Lazy-Loader: lädt Modul-Code für den Typ bei Bedarf (import() + sha256)
└─ erzeugt das versionierte Kind-Element und reicht hass/config durch
        │
        ├─ Frei:    light, sensor, scene, quick-action, hero, status, …
        └─ Premium: rooms, camera, system, climate, calendar, weather, …
```

Die Shell existiert im Kern bereits als `NeoCard` (`neo-dashboard.js`,
`class NeoCard`). Für 1.0 wird sie um **Tier-Metadaten**, **Lazy-Loading pro
Typ** und das **Lizenz-Gate** erweitert.

### Lizenz-Gate (Skizze)

```js
// in NeoCard.setConfig(), vor dem getCard(type)-Check
const meta = NeoDashboardRegistry.getMeta(type);
if (meta?.tier === "premium" && !NeoLicense.isActive()) {
  this.innerHTML = `<ha-card class="neo-locked">
    🔒 „${meta.name}" ist ein Premium-Modul –
    <a href="${NEO_LINKS.patreon}" target="_blank" rel="noopener">freischalten</a>
  </ha-card>`;
  return;
}
```

### Lazy-Loading (Skizze)

```js
async function neoLoadModule(code, expectedSha) {
  if (expectedSha) {
    const buf  = new TextEncoder().encode(code);
    const hash = [...new Uint8Array(await crypto.subtle.digest("SHA-256", buf))]
      .map(b => b.toString(16).padStart(2, "0")).join("");
    if (hash !== expectedSha) throw new Error("Integritätsprüfung fehlgeschlagen");
  }
  const url = URL.createObjectURL(new Blob([code], { type: "text/javascript" }));
  try { await import(url); } finally { URL.revokeObjectURL(url); }
}
```

Die versionierten Element-Tags (bestehendes Verhalten) bleiben erhalten, sodass
Modul-Updates weiterhin ohne Browser-Reload live gehen.

## Modul-Manifest

Jedes Modul trägt ein Manifest (vorangestellter Header-Kommentar **oder**
Begleitdatei). Pflichtfelder fett.

```yaml
id: rooms             # eindeutig, kebab-case  (PFLICHT)
name: Rooms Card      # Anzeigename            (PFLICHT)
version: 1.0.0        # SemVer                 (PFLICHT)
type: card            # card | layer           (PFLICHT)
tier: premium         # free | premium         (PFLICHT)
min_neo: "1.0.0"      # min. Neo-Version
min_ha:  "2024.8.0"   # min. Home-Assistant-Version
author: bkstudy2025
description: "Raum-Übersichtskarte mit …"
icon: rooms
dependencies: []      # andere Modul-ids, die zuerst geladen werden müssen
```

## Store-Index (`neo-modules/index.json`)

```json
[
  {
    "id": "rooms",
    "name": "Rooms Card",
    "version": "1.0.0",
    "type": "card",
    "tier": "premium",
    "author": "bkstudy2025",
    "description": "Raum-Übersichtskarte …",
    "screenshot": "modules/rooms/preview.png",
    "entry": "modules/rooms/neo-rooms-card.js",
    "sha256": "…",
    "min_neo": "1.0.0"
  }
]
```

- Auslieferung über jsDelivr:
  `https://cdn.jsdelivr.net/gh/bkstudy2025/neo-modules@<tag>/<entry>`
- Der Store lädt **eine** Datei (`index.json`) statt N Discussion-Abfragen →
  kein GitHub-Rate-Limit mehr (behebt den aktuellen Fehler
  „Store konnte nicht geladen werden (GitHub-Limit?)").
- `version` im Index ermöglicht **„Update verfügbar"-Badges** pro installiertem
  Modul.
- Optional: GitHub Discussions als Einreichungskanal behalten und `index.json`
  per GitHub Action automatisch generieren – für Autoren ändert sich nichts,
  Nutzer treffen aber nie das Limit.

## Premium-Vertrieb (Patreon)

- Premium-Module liegen in einem **privaten** Repo / hinter Patreon-Gate.
- Der Nutzer hinterlegt einen Lizenz-/Patreon-Token; `NeoLicense.isActive()`
  prüft ihn (Detail-Design separat).
- Free-Typen funktionieren immer; Premium-Typen zeigen ohne Lizenz die
  „🔒"-Kachel mit Freischalt-Link.
